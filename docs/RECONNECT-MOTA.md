# 魔搭（ModelScope）服务器能实现这条重连/反推链路吗

> 结论：**能，但必须换一种持久化主体**。魔搭创空间的容器是易失的（重启即清盘、无持久卷、端口锁 7860），
> 所以「服务端把房间壳/seed 落盘，重启后读回来」那条路在魔搭上**无效**。
> 可行形态是**客户端携带恢复包**：每个玩家把自己的 `seed + 房间配置 + 快照` 存在浏览器本地，
> 重连后交给新容器，由它「以客户端携带的状态重建」。代价是需要新增两处协议字段，并且恢复局必须标为非排位。

## 一、魔搭的硬约束（与服务器联机的差异）

| 维度 | 普通服务器 / p2p 房主 | 魔搭创空间 |
|---|---|---|
| 进程重启后磁盘 | 保留（可挂卷） | **清空**（平台每次 push 全树重建镜像） |
| 房间壳/seed 落盘 | 可行（T1） | **不可行**（重启即失） |
| 监听端口 | 自由 | 锁 7860（nginx 在前，游戏退 3120） |
| root / systemd | 有 | 无 |
| 跨重启还能活的东西 | 卷、外部存储 | **只有玩家浏览器本地存储** |

因此「反推」在魔搭上的唯一稳定载体是**客户端**。

## 二、链路（魔搭版）

```
对局进行中（每 5s 或阶段切换时，客户端各自本地存一份恢复包）
  localStorage['sp.recover.<roomCode>'] = {
    v: 1, seed, mode, difficulty, modeId,
    snapshot: { roomCode, playerId, phase, round, lp, funds, board[], hand[], shop, stats }
  }

容器重启（发版/平台重建）→ 客户端 ws 断开 → 重连 → hello 拿到新 playerId
  ↓
客户端发现「本地有恢复包 + 房间码」→ 发 b.recover { bundle }
  ↓
新容器（内存空）：第一份包 → 建房间壳 + 重建 Match（标记 recovered）
                  后续包 → 必须与第一份一致（seed/mode/difficulty/modeId/roomCode 全等），否则拒绝
  ↓
重建成功 → 广播 m.public（带 recovered: { at, drift:[...] }）→ 从下一个 PREP 继续
```

一致性校验已经实现：`shared/matchSnapshot.mjs` 的 `agreeOnBundles()`——任何一项不一致就返回冲突清单，
调用方放弃恢复、当新局处理（防「挑一个对自己有利的 seed」）。

## 三、需要新增的两处协议（都很小）

| 方向 | 消息 | 内容 | 为什么必须 |
|---|---|---|---|
| S2C | `m.private` 增加 `seed`（或 `m.public.seed`） | uint32 | 客户端现在**拿不到 seed**（审计确认 `views.js`/`player/views.js` 都没有），没有它就无法让新容器重建出同样的关卡/波次 |
| C2S | `b.recover { bundle }` | 见上 | 现有 C2S 全是操作意图（`room.*` / `g.*` / `b.progress` / `b.result`），**没有任何「状态上报」消息**（审计确认） |

`b.progress` / `b.result` 不能替代：它们只覆盖**单场战斗**的进度与结果，且服务端按「事件」处理
（跨过结算就忽略），不是整局状态。

## 四、容差与限制（与通用版一致，另加魔搭特有两条）

| 项 | 魔搭上的处理 |
|---|---|
| 玩家棋盘/手牌/资金/生命/商店 | 客户端上报，精确（以最后一份包为准） |
| 共享卡池剩余 | 按 `cap − 当前持有` 重算，debt 归零（漂移） |
| AI 布阵 | 新 `rngBots` 重派（漂移）；AI 战斗由 seed 完全重算 |
| 进行中的战斗 | 丢弃，恢复到下一个 PREP |
| **魔搭特有①：玩家清缓存/换设备** | 那份包丢失 → 该玩家按默认值补（LP 用公共视图里的值，棋盘为空），或拒绝恢复（由房主/多数决定） |
| **魔搭特有②：多人同时恢复** | 先到的包建壳，后到的按一致性合并；不一致直接拒绝恢复 |

## 五、安全（魔搭是公开环境，这条不能省）

1. **seed 必须多数一致**：单份包不足以建局（否则一人可挑 seed）；
2. **恢复局不计排行、不进学习库**（客户端可谎报 LP/棋盘）；
3. **单房间只恢复一次**（避免反复「回滚」刷状态）；
4. **与公共视图交叉校验**：快照里的 `boardCount`/`lp` 要和 `m.public.players[]` 对得上，对不上就丢弃该份包。

## 六、落地状态

| 项 | 状态 |
|---|---|
| 快照/恢复包格式与校验（白名单、有界、一致性） | **已实现**：`shared/matchSnapshot.mjs`（`sanitizeSnapshot` / `sanitizeBundle` / `agreeOnBundles`）+ 9 例测试 |
| 客户端本地存包 | **未做**（需要在 `m.private` 到达时写 localStorage，节流 5s/阶段切换） |
| `seed` 下发 | **未做**（一行：`m.private` 或 `m.public` 增加 seed） |
| `b.recover` 协议 + 服务端重建器 | **未做**（重建器与通用版共用，见 `docs/RECONNECT-LOCAL-REBUILD.md` 第四节） |
| 非排位标记 / 交叉校验 | **未做**（规则已定，见上） |

## 七、结论一句话

魔搭上**能做**，但要把「服务端持久化」换成「客户端携带」：多两个小字段（`seed` 下发、`b.recover` 上报），
重建器与通用版完全共用。代价是恢复局必须非排位，且只能在重连窗口（10 分钟）内、且玩家没清缓存时生效。
